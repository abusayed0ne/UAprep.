# MVP implementation sequence

1. **Stage A—Foundation — complete:** repository, environment validation, database baseline, identity/session contracts, tenancy, RBAC/attributes, audit, design tokens, health checks and test harness.
2. **Stage B—Academic configuration — complete:** universities/programs, evidence registry, versioned patterns, curriculum taxonomy, guarded API, publication validation, and initial migration.
3. **Stage C—Question operations — complete:** immutable versions, assignments, lint, exact duplicate detection, SME review, independent validation, fairness/rights, approval, workflow history, quarantine, and production bank API.
4. **Stage D—Mock creation — complete:** blueprints, section constraints, composer API, machine-readable validation, exact version pinning, exposure checks, immutable versioning, and atomic publishing.
5. **Stage E—Student exam — implementation complete:** onboarding targets, library, immutable snapshot, autosave revisions, server timer, idempotent submission, and objective scoring.
6. **Stage F—Results — implementation complete:** score/sections, post-score review, performance history, and question reporting.
7. **Stage G—Commerce — implementation complete:** products/prices, trusted server orders, validated-payment boundary, idempotent payment records, and entitlements.
8. **Stage H—Hardening — code gates complete; deployed checks pending manual setup:** authorization/tenant/key-leak boundaries, security headers, correlation IDs, CI gates, migration validation, and documented infrastructure checks.

Only after stable MVP: preparation, practice/mistakes, mastery/readiness, planning, tracker and governed AI assistance.

## Safe configuration assumptions

Pattern sections/counts/marks/durations/negative marking/calculator/pass rules; program applicability; evidence review cadence; workflow transition policy; lint thresholds; similarity and psychometric sample thresholds; blueprint coverage/difficulty/exposure; scoring/rounding/review-release rules; feature flags; session/rate-limit durations; retention; payment provider; and design tokens. Defaults are conservative and not university facts.
